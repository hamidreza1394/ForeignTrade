# مدل مفهومی داده

## مفاهیم پایه
- **Tenant**: مشتری نرم‌افزار و مرز اصلی جداسازی داده.
- **Company**: شرکت بازرگانی/واردکننده/عملیاتی درون Tenant.
- **User**: هویت ورود.
- **UserCompanyMembership**: عضویت کاربر در شرکت و وضعیت آن.
- **Role / Permission**: مجوزهای قابل تخصیص در دامنه شرکت یا سطح سامانه.
- **OperationalPeriod**: دوره کاری بازرگانی با بازه و وضعیت مستقل از دوره مالی حسابداری.
- **AuditEvent**: رخداد قابل ردیابی.

## الزامات
- کلیدهای اصلی Guid.
- تاریخ‌های سرور UTC؛ نمایش شمسی/محلی فقط در UI با تبدیل کنترل‌شده.
- RowVersion یا سازوکار concurrency برای داده‌های قابل ویرایش.
- حذف نرم در جایی که نیاز کسب‌وکار و الزامات نگهداری اجازه می‌دهد؛ نه به‌صورت blanket برای همه موجودیت‌ها.
- یکتایی نام کاربری باید دامنه مشخص داشته باشد (سراسری یا در Tenant) و قبل از پیاده‌سازی تصمیم بگیرد.
- دوره عملیاتی باید وضعیت‌های تعریف‌شده، بازه معتبر و قواعد ثبت/مشاهده داشته باشد.
- مدل نهایی و قیود دیتابیس پس از استخراج نیازمندی‌های دقیق دوره و واردات ثبت می‌شود.

## نکته مهم
مدل `Company` و `FiscalPeriod` فرانو عیناً کپی نمی‌شود. ساختار ForeignTrade مستقل است؛ فقط UX و الگوهای فنی قابل‌تعمیم منتقل می‌شوند.
