# امنیت و مرزبندی داده

## احراز هویت
- از مکانیزم استاندارد و به‌روز ASP.NET Core Identity یا سازوکار معادلِ تأییدشده استفاده شود؛ هش رمز سفارشی ممنوع.
- cookie نشست HttpOnly، Secure در HTTPS، SameSite مناسب و محافظت CSRF.
- محدودسازی تلاش ورود، پاسخ خطای غیرقابل‌استفاده برای کشف حساب، ثبت رخدادهای امنیتی بدون ثبت رمز/توکن.
- اعتبارسنجی فعال بودن حساب و تغییر اعتبارنامه/لغو نشست مطابق سیاست نشست.

## مجوزدهی
- تمام مجوزها در سرور ارزیابی شوند.
- شناسه Tenant/Company/Period ارسالی صرفاً selector غیرقابل‌اعتماد است.
- هر درخواست باید عضویت فعال و مجوز منبع را بررسی کند.
- دسترسی مدیر سیستمی cross-tenant باید صریح، محدود و audit شود.
- عملیات Import/Export، فایل، گزارش، job و raw SQL نیز باید مرزهای Tenant/Company را رعایت کنند.

## جداسازی
- TenantId و CompanyId در رکوردهای مربوطه.
- EF Core query filters به‌عنوان defense-in-depth، همراه با کنترل صریح در Application layer.
- تست منفی: دسترسی به رکورد Tenant دیگر، Company غیرعضو، دوره بسته و شناسه دستکاری‌شده باید رد شود.
- عملیات چندشرکتی تنها روی شرکت‌های مجاز همان کاربر.

## اسرار و رمزنگاری
- هیچ secret در سورس، تست fixture یا مستندات.
- کلید خصوصی امضای لایسنس فقط در محیط امن صادرکننده آینده؛ این پروژه کلید صدور ندارد.
- داده حساس در log پاک‌سازی شود؛ retention و دسترسی log تعریف شود.

## فایل‌ها
- اندازه/نوع/نام فایل اعتبارسنجی، ذخیره‌سازی خارج از web root، نام فیزیکی غیرقابل‌حدس، بررسی دسترسی هنگام دانلود، hash و version ثبت شود.
